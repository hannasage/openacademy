Host your own connector.

Each owner runs a private connector on Vercel with a PostgreSQL database. This database holds temporary setup permission and the public hub description. Editable learning files stay on your computer. Published snapshots live in your own Supabase project.

Prepare the connector

  1. Use your own copy of Schola. Import that repository into Vercel. The public deployment template is not available while this repository is private.
  2. Create a PostgreSQL database, then apply the connector schema from backend/setup/schema.sql. Use an encrypted connection with certificate verification.
  3. Register two separate Supabase setup apps: one for discovery and inspection, and one for installation. Set their exact return addresses to https://your-hub/setup/callback/discovery and https://your-hub/setup/callback/install.
  4. Follow the repository's connector guide to set the server environment values, build the hosted output, and generate a short-lived setup code. Provider secrets belong in Vercel settings, never in the Schola setup page. Enter only the one-time setup code at your verified connector address.
  5. Open your connector's /setup page. Unlock it with the code, choose a project, review the proposed changes, and grant installation permission only when you are ready.

Use the manual route

You can configure a Supabase backend with the migrations and owner-access steps in backend/README.md. Publish a valid Schola hub description at /.well-known/touchline.json, then enter that hub address in your local app.

Backend setup does not create a learning session. Sign in with your owner email in Schola after the hub is ready. Google and Apple appear only if you enable them in your own backend.

Keep learning locally

You can close setup and continue using your local curricula. A cancelled setup may leave completed installation steps in the chosen project; review those steps before trying again.
