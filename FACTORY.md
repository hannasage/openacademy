# Schola factory

This factory is an agent team with a bounded workflow for this repository.

## Charter

- Purpose: Develop the local learning hub and its native reading companion.
- Customer: The owner and learners named in the accepted product plan.
- Boundary: Preserve readable local progress, drafts, and recovery data. Keep account sign-in separate from backend setup. Experiments move to another company only through Hanna.
- Stage: Use the current accepted learning-hub plan and release evidence.
- Measures: accepted outcomes, founder interventions, waiting time, review cycles, and defects after release. Missing evidence stays unknown.
- Work lanes: one primary accepted task and one small friction task. Manual members run one at a time.
- Stakeholder approvals: Hanna retains product boundaries, public messages, spending, releases, and irreversible actions. Client approvals remain separate.
- Review cadence: status on request and manual weekly review. No trigger or article start date is activated.

## Start a manual task

In this repository, ask the existing agent to read AGENTS.md and FACTORY.md.
Name the accepted task, its input revision, and factory-intake.
Use factory-intake for a read-only status pass.
Use factory-delivery only for an authorized task.
Use factory-review in another session for independent review.
Use factory-handoff for research, articles, and release-health requests.

The manual team plan names Claude Code's documented sonnet model alias.
Agent files inherit the existing session model.
Codex receives the factory skills, with no agent profiles that claim enforced tool limits.
The definition starts no model and authorizes no model API call.

## Acceptance

Run npm run verify. Add browser or appearance tests when AGENTS.md requires them.
Keep code completion, review, visual review, owner acceptance, and release separate.
An independent reviewer must use another session and name the exact reviewed revision.

## Handoffs and records

Use factory-handoff for the request and result fields.
Keep private run records outside version control.
The shared arms receive only the accepted input and its approved data boundary.
No relay service or scheduler runs in Bowerloom v0.8.
Members receive their task from a person and return their evidence to that person.

## Install on another checkout

Use a Bowerloom 0.8.0-beta.1 build.
The v0.7 command does not support this harness installation.
In this repository, run `bowerloom harness install --json` to read the plan.
Read the changed files and the reported engine support.
If the plan matches the accepted scope, run the same command with `--approve <revision>`.
Retain the private installation record outside the repository.
Run `bowerloom harness drift --check --json` after installation.
